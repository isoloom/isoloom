## Compose

- `name` ✓: the Compose project name
- `networks.*.cidr` ✓: a Compose network with that subnet
- `networks.*.internet` ✓: no default route for offline machines (Docker's internal network when nothing routes)
- `networks.*.gateway` ✓: the gateway machine at .1 with forwarding; machines behind it route through it
- `reach[].from` ✓: a router container filtering with nftables
- `reach[].to` ✓: the router's rules
- `reach[].ports` ✓: the router's rules, per port
- `inputs` ✓: variables read from the shell at start
- `machines.*.networks` ✓: a fixed address on each network; names across networks
- `machines.*.services[].port` ✓: a healthcheck, so `depends_on` and `up --wait` wait for it
- `machines.*.inputs` ✓: environment of that machine and its init jobs only
- `machines.*.resources.cpus` ✓: a CPU limit
- `machines.*.resources.memory_mb` ✓: a memory limit
- `machines.*.depends_on` ✓: starts after its dependencies answer (and their init jobs finish)
- `machines.*.access` ✓: checks run from its network namespace (a stand-in when the runner supplies it)
- `machines.*.docker.image` ✓: the service's image
- `machines.*.docker.build` ✓: a build from the project folder
- `machines.*.docker.init` ✓: one-shot jobs in its network namespace, after it answers
- `checks` ✓: a `check` profile running them from the access side

## Vagrant

- `name` ✓: VM labels and network names
- `networks.*.cidr` ✓: a private network (VirtualBox internal network, libvirt network)
- `networks.*.internet` ✓: new connections out through the NAT interface blocked after provisioning
- `networks.*.gateway` ✓: forwarding on the gateway; machines move behind it after provisioning
- `reach[].from` ✓: a router VM filtering with nftables
- `reach[].to` ✓: the router's rules
- `reach[].ports` ✓: the router's rules, per port
- `inputs` ✓: values read from the environment at start
- `machines.*.networks` ✓: a fixed address on each network; names in /etc/hosts
- `machines.*.services[].port` ✓: machines depending on it wait until it answers
- `machines.*.inputs` ✓: environment of that machine's provisioning only
- `machines.*.resources.cpus` ✓: the VM's CPUs on every provider
- `machines.*.resources.memory_mb` ✓: the VM's memory on every provider
- `machines.*.resources.disk_gb` planned: the box's disk size is used as is
- `machines.*.depends_on` ✓: boots after its dependencies, then waits until they answer
- `machines.*.access` ◐: a VM like the others when it has `vm:`; not yet: checks don't run from it
- `machines.*.vm.os` ◐: Vagrant boxes for debian-12, ubuntu-24.04 and kali; not yet: Windows
- `machines.*.vm.provision` ✓: `.sh` steps, and Ansible run inside the VM
- `checks` planned: with the check runner on VMs

Terraform (Proxmox, one cloud VM per machine) and Ludus have no generator yet.
